# Sigil — a custom icon system for Claude Code projects

- **Date:** 2026-09-25
- **Status:** active — the founding plan for this repo
- **Type:** plan
- **Origin:** the Frozone tool-icon build (`plans/2026-09-25-tool-icons.md`, `apps/web/src/components/icons/`). 45 two-colour icons drawn by Opus agents in one afternoon replaced Lucide across two portals. Sigil turns that afternoon into a repeatable tool.

## 1. The idea in one paragraph

A project stops using Lucide. Instead it has an **`icon.md` at the repo root** — the icon style bible (grid, stroke, corner radii, layer roles, colour tones, detail budget, vocabulary, the reference set) — and a **`sigil` CLI + Claude Code skill** that draws icons *in that style* on demand, using headless Claude Code (the developer's own Claude Code auth, not a separate API key). Starting out, Sigil proposes five style directions drawn with the project's *real* nav items and shows them in a local lab page, in context, down to 16px; the developer mixes and iterates ("B's colours on C's tile, rounder corners") until `icon.md` is written. After that, `sigil draw pipeline booking roster …` returns finished, reviewed SVGs plus typed components — and every drawing has been rendered, looked at and fixed by the model before you ever see it.

## 2. What made the Frozone icons good (build these in, not on top)

1. **The model looked at its own work.** Each agent wrote SVG, rendered a contact sheet, *read the PNG*, fixed, and repeated 2–3× per icon. One-shot SVG is where AI icons go bad. The render → look → fix loop is the product.
2. **Geometry is separate from colour.** An icon is one drawing in ordered layers with *roles* — `plane` (the body's flat fill), `line` (2px strokes, all detail), `dot` (small solid marks). A *tone* paints roles (tile / inline / on-dark). So "five styles" is five colour maps over the same drawings, and a rebrand is a CSS change.
3. **Draw the real object.** A jersey for Pro shop, a batting helmet for Roster, a gauge for Boost. The prompt has to push past the generic symbol-on-a-document.
4. **Family review catches what single icons can't.** Three houses (Today / Households / Boost) and a practice plan that read as wifi were only visible on the full sheet. Silhouette collisions and 16px mush need a dedicated pass.
5. **A small reference set sets the hand.** 12 hand-reviewed icons were the "house hand" every later icon matched. `icon.md` must carry references, not just rules.

## 3. The pieces

### 3.1 `icon.md` (repo root) — the style bible

Human-readable, versioned, and machine-parseable (YAML frontmatter for the numbers, prose for the taste):

```md
---
sigil: 1
grid: 32            # viewBox 0 0 32 32
keyline: [3, 29]    # everything inside
stroke: 2           # line role width at grid scale
caps: round
joins: round
radius: { sheet: 3, box: 2, bar: 1.2 }
optical: { circle: 24, square: 22, tall: 25, wide: 25 }
roles: [plane, line, dot, accent]
tones:
  tile:    { bg: "linear-gradient(160deg,#A12A4C,#62122B)", line: "#FFFFFF", plane: "rgba(255,255,255,.26)", radius: "27%" }
  inline:  { line: "#8A1E3D", plane: "#EDB9C8" }
  on-dark: { line: "rgba(255,255,255,.88)", plane: "rgba(255,255,255,.2)" }
detail_budget: { inner_marks: [2, 5], min_gap: 2.5, min_px: 16 }
references: [forms, point-of-sale, pro-shop, orders, discounts, at-risk]
---
# Icon style
Voice: … (what this product's icons feel like, in words)
## Drawing rules … ## Vocabulary (this domain's real objects) … ## Never …
```

`sigil` treats `icon.md` as the only source of truth; its hash keys the cache.

### 3.2 The icon source format

`icons/src/<name>.svg` — plain SVG, no colours, role groups:

```svg
<svg viewBox="0 0 32 32" data-sigil="1" data-brief="the batting helmet an athlete wears">
  <g data-role="plane"><path d="…"/></g>
  <g data-role="line"><path d="…"/><circle …/></g>
  <g data-role="dot"><circle …/></g>
</svg>
```

Portable (any framework), diffable, and hand-editable in Figma/Inkscape with the roles intact. The brief rides along so a redraw knows the intent.

### 3.3 Outputs (`sigil build`)

- `icons/dist/react/<Name>.tsx` + `Icon.tsx` (`<Icon name="roster" tone="tile" size={44} />`) with a typed `IconName` union — strict TS, no `any`.
- `icons/dist/icons.css` — the tone classes generated from `icon.md` (tones are CSS, so theming never touches drawings).
- `icons/dist/sprite.svg` and per-tone flat SVGs for non-React consumers (emails, PDFs, favicons).
- `icons/dist/sheet.html` — the contact sheet (see 3.5).

### 3.4 The engine

- **Headless Claude Code**: `claude -p "<task>" --output-format json --append-system-prompt-file .sigil/system.md --allowedTools Read,Write` run in a scratch dir per job. It uses whatever auth the developer's Claude Code already has (subscription or key) — no separate API billing. Wrapped behind one `runClaude(job)` adapter so the **Claude Agent SDK** (`@anthropic-ai/claude-agent-sdk`, same agent loop in-process, streaming + structured output) can replace it. **Day-1 spike:** confirm which auth modes each path honours on the dev's machine and document it in the README; don't assume.
- **Model:** the strongest available Claude (Opus-class) for drawing; a cheap model only for lint explanations.
- **The loop inside a job** (this is the product): draw → `sigil render` (resvg-js → PNG sheet: 128px on grid, tile 64/44, inline 24/20/16, on-dark 20) → the model *Reads the PNG* → critique against `icon.md` + neighbours → fix → repeat until the model passes it (max 4 turns). The job returns SVG + a one-line rationale + its self-critique.
- **Concurrency:** ≤3 parallel jobs by default (configurable), batches of ~10 icons per job so a job can see its own siblings; content-hash cache (`icon.md` hash + brief + references) so unchanged icons never redraw.

### 3.5 Machine checks (deterministic, run after every draw)

- **Schema lint:** only path/circle/rect/line/polyline; roles present; no fill on `line`, no stroke on `plane`; stroke width = `stroke`; coordinates on the half-grid; bounding box inside `keyline`.
- **16px legibility:** rasterise at 16px; flag strokes closer than `min_gap`, detail islands that vanish, and >N% ink coverage (mush).
- **Silhouette collisions:** rasterise the union of all layers at 24px, compare every pair (IoU / perceptual hash); flag pairs above a threshold *within the same group* (the three-houses bug). Output feeds the next redraw's prompt as "must not look like X".
- **Optical size:** ink bbox vs the `optical` targets; flag outliers so the family sits level.

### 3.6 The lab (the fun part)

`sigil lab` serves a local page (Vite, port per project, never 3000) that is the whole UX, like the Frozone icon-lab artifact:

- **Directions view** (at `sigil init`): five columns, each a draft `icon.md` rendered on 8–12 of the project's real nav items, in real contexts — a grid tile, a sidebar row, a navy tab strip, a 16px chip — plus the current Lucide set for comparison. Controls: pick one, or **mix** ("A's line weight + C's tone + D's corner radius") which writes a new draft and re-renders only the tones (no redraw needed when only colours change).
- **Iterate:** a text box per direction ("rounder", "less detail", "more baseball") → a job revises the draft `icon.md` + redraws its samples. History of drafts kept in `.sigil/directions/`.
- **Library view** (after init): every icon with approve / redraw-with-note / edit-brief; lint and collision flags inline; side-by-side before/after on redraw.
- **Commit:** writes `icon.md`, `icons/src/*.svg`, runs `build`.

### 3.7 Inventory + migration

- `sigil scan` finds every `lucide-react` import and usage, groups them by route/nav, and proposes an icon list with names and one-line briefs derived from labels and routes (the dev edits the list).
- `sigil migrate` is a codemod: `<ShoppingCart className="h-4 w-4" />` → `<Icon name="point-of-sale" size={16} />`, leaving Lucide in place for utility glyphs the dev marks as "keep" (chevrons, X, plus — utility icons stay stock; *tool* icons go custom).

### 3.8 The Claude Code skill

`/sigil` skill (`skills/sigil/SKILL.md`) so the same flow runs inside an interactive session: "draw icons for the new Payroll and Waivers pages" → the skill reads `icon.md`, writes briefs, calls `sigil draw`, opens the sheet, reports. The skill is the drawing brief + workflow; the CLI is the machinery. Both read the same `system.md`.

## 4. The system prompt (draft — `.sigil/system.md`)

> You are a senior icon designer drawing a custom icon family for one product. The style is fixed by `icon.md` (attached) — follow it exactly; it overrides your instincts.
>
> **Format.** Output SVG on a {grid}×{grid} viewBox with `<g data-role>` groups in paint order: `plane` = one flat fill for the object's body, never carries detail; `line` = {stroke}px round-cap round-join strokes, all detail lives here; `dot` = small solid marks in the line colour; `accent` only if `icon.md` defines it. No colours, no `style`, no transforms, no text. Coordinates on the half-grid.
>
> **Draw the real object** the tool is about, the thing this product's users would recognise from their world ({vocabulary}). Never a generic document with a symbol on it unless the tool *is* a document. Metaphors only when there is no object.
>
> **Budget.** {inner_marks} inner marks. Everything must survive {min_px}px: strokes closer than {min_gap} units merge — move them or cut them.
>
> **Family.** Match the references' weight, radii and density. Your icon must not share a silhouette with any icon in `neighbours` (attached as a sheet). Center visual mass, hit the optical size for its shape.
>
> **Process.** Draw, then run `sigil render <file>`, Read the PNG, and critique it: legibility at 16px, silhouette vs neighbours, optical size, whether a stranger would name the tool from the 20px version. Fix and re-render until it passes (max 4 rounds). Return JSON `{ name, svg, rationale, critique, rounds }`.

## 5. Milestones

| M | Delivers | Done when |
|---|---|---|
| **M0 spike** | `runClaude` adapter (headless CLI + Agent SDK), auth modes documented; resvg render of one hand-written icon | A job draws one icon from a hard-coded brief, renders, reads its PNG, revises, returns JSON |
| **M1 core** | `icon.md` parser (zod), SVG source format, `render`, schema lint, `draw` with the loop, cache | `sigil draw roster booking` in a fixture project yields lint-clean SVGs that pass the loop |
| **M2 family** | 16px + collision + optical checks feeding redraws; `build` (TSX + CSS tones + sprite + sheet) | Seed the Frozone 45 as a fixture: checks flag the three houses and the wifi plan; `build` output typechecks strict |
| **M3 lab** | `sigil init` directions (5 drafts on real nav items), mix, iterate, library review, commit | A fresh project goes from no `icon.md` to 20 approved icons without leaving the lab |
| **M4 migrate** | `scan` + `migrate` codemod with a keep-list | A Lucide-heavy fixture swaps tool icons, keeps chevrons, typechecks |
| **M5 skill** | `/sigil` skill + README; publish as a package | Run inside Claude Code on a real repo (frozenropes is the first customer) |

Stack: TypeScript, Bun, strict TS + zod at every boundary (icon.md, SVG parse, job JSON); resvg-js for raster; Vite + React + Tailwind for the lab; no database — the repo is the store.

## 6. Decisions to make on day one

1. **Name** — "Sigil" is a working title.
2. **Where it lives** — its own repo + npm package (`sigil` CLI) with the skill installed by `sigil install-skill`; projects keep only `icon.md` + `icons/`.
3. **Colour roles** — cap at plane/line/dot/accent (four), or allow per-icon extra roles? Recommend four: more roles is where families stop looking like families.
4. **Utility icons** — draw our own chevrons/X/plus too, or keep Lucide for utilities? Recommend keep — the win is tool icons.
5. **Frozone back-port** — convert `apps/web/src/components/icons/glyphs/*.ts` to the `icons/src/*.svg` format and let Sigil own it (the 45 + the brief become the first `icon.md` and reference set).
